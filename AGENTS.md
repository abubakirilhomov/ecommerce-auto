# AGENTS.md — Инструкции для AI-агентов (Antigravity / Codex)

Ты работаешь в учебном коммерческом проекте **AutoUz** (онлайн-магазин для автосалонов Узбекистана).
Твоя цель — помогать ученику писать чистый, понятный, масштабируемый код и объяснять ключевые решения простым языком.

---

## 1. Обязательный контекст перед началом работы
Перед выполнением любой задачи изучи:
1. `docs/ARCHITECTURE.md` — структура папок, паттерны компонентов и схема `db.json`.
2. `task.md` — текущие задачи и границы ответственности ученика.
3. `docs/GIT_RULES.md` — правила именования веток и коммитов.

---

## 2. Технические стандарты проекта
- **Стек**: HTML5, Tailwind CSS v4 (`@tailwindcss/vite`), DaisyUI v5 (`@plugin "daisyui"` в `src/styles/main.css`), Vanilla JS (ES Modules), Vite, GSAP, Swiper.js, `json-server`, PWA (`vite-plugin-pwa`). **Не создавай** `tailwind.config.js` от v3.
- **Корневые контейнеры `index.html`**: `#app-header`, `#app`, `#app-footer`, `#toast-root`.
- **React-Ready подход**:
  - Пиши функциональные компоненты в `src/components/` и страницы в `src/pages/`.
  - Держи данные и запросы к API строго в `src/services/`, а состояние — в `src/core/store.js`.
  - Не смешивай бизнес-логику, запросы к API и HTML-шаблоны в одном большом файле.
- **Безопасность (обязательно!)**:
  - Все динамические строки из API или пользовательского ввода перед вставкой в HTML экранируй через `escapeHtml()` (`src/utils/sanitize.js`).
  - Никогда не используй `eval()`, `new Function()` или небезопасный `innerHTML` с сырыми пользовательскими данными.
  - Валидируй формы через `src/utils/validators.js` (например, узбекские номера `+998...`).
- **Адаптивность и UI**:
  - Используй классы Tailwind CSS и компоненты DaisyUI (`btn`, `card`, `badge`, `modal`, `input`, `select`).
  - Проверяй, чтобы верстка корректно выглядела на мобильных экранах (375px+) и десктопе.

---

## 3. Границы ответственности (Scope Guard)
- Работай **только** в рамках задачи, которую указал ученик из `task.md`.
- **Не изменяй** файлы ядра (`src/core/*`) и схему `server/db.json`, если задача явно не относится к ядру/бэкенду (или если пользователь не является архитектором/тимлидом).
- Сохраняй существующие комментарии и документацию.

---

## 4. Обновление `task.md` и `done.md`
- Когда задача выполнена и проверена (`npm run build` или ручная проверка в dev-сервере):
  1. Отметь задачу в `task.md` как `[x]`.
  2. Добавь запись в `done.md` по установленному шаблону.
- Объясни ученику в конце ответа (в 3–5 пунктах), что именно было сделано и как это проверить в браузере.
